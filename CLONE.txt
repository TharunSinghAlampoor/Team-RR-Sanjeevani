1. EXECUTIVE SYSTEM OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
Team-RR-Sanjeevani is a full-stack, enterprise-grade E-Commerce and Healthcare 
product management system built with a modular, decoupled Client-Server architecture.

System Architecture Layers:
  [ React 18 Frontend ] <--- HTTPS / REST (JSON) ---> [ Spring Boot 4.1 Backend ]
      (Vite 6 + CSS)                                        (Java 21 + JWT)
                                                                 |
                                                          [ MySQL 8.4 DB ]

Core System Objectives:
  1. Secure authentication and granular Role-Based Access Control (ADMIN, CUSTOMER).
  2. High-performance session management combining stateless JWT and stateful server session tracking.
  3. Secure multi-step password reset flows backed by OTP verification (Console/Email SMTP).
  4. Robust rate-limiting on sensitive auth endpoints to prevent brute-force attacks.
  5. Scalable catalog and order handling (Categories, Products, Images, Carts, Orders).

3. DATABASE SCHEMA & ENTITY DESIGN
--------------------------------------------------------------------------------
Database Name: `E-Commerce`

Entity Relationship Overview:
  [categories] (1) <---> (N) [products] (1) <---> (N) [productimages]
  [users] (1) <---> (N) [sessions]
  [users] (1) <---> (N) [otps]
  [users] (1) <---> (N) [jwt_tokens]
  [users] (1) <---> (N) [cart_items] (N) <---> (1) [products]
  [users] (1) <---> (N) [orders] (1) <---> (N) [order_items] (N) <---> (1) [products]

Detailed Schema Definition:
  1. `users`
     - user_id (INT, PK, AUTO_INCREMENT)
     - full_name (VARCHAR 255, NOT NULL)
     - email (VARCHAR 255, UNIQUE, NOT NULL)
     - phone_number (VARCHAR 20, UNIQUE)
     - password (VARCHAR 255, NOT NULL - BCrypt Hash)
     - role (ENUM('ADMIN', 'CUSTOMER'), NOT NULL)
     - created_at, updated_at (TIMESTAMP)

  2. `sessions`
     - session_id (INT, PK, AUTO_INCREMENT)
     - user_id (INT, FK -> users.user_id)
     - jwt_token (VARCHAR 512, NOT NULL)
     - login_time (DATETIME, NOT NULL)
     - expiry_time (DATETIME, NOT NULL)
     - active (BOOLEAN, DEFAULT TRUE)

  3. `otps`
     - otp_id (INT, PK, AUTO_INCREMENT)
     - user_id (INT, FK -> users.user_id)
     - otp_code (VARCHAR 6, NOT NULL)
     - generated_time (DATETIME, NOT NULL)
     - expiry_time (DATETIME, NOT NULL)
     - verified (BOOLEAN, DEFAULT FALSE)

  4. `categories`
     - category_id (INT, PK, AUTO_INCREMENT)
     - category_name (VARCHAR 255, UNIQUE, NOT NULL)

  5. `products`
     - product_id (INT, PK, AUTO_INCREMENT)
     - name (VARCHAR 255, NOT NULL)
     - description (TEXT)
     - price (DECIMAL 10,2, NOT NULL)
     - stock (INT, NOT NULL)
     - category_id (INT, FK -> categories.category_id)
     - created_at, updated_at (TIMESTAMP)

  6. `productimages`
     - image_id (INT, PK, AUTO_INCREMENT)
     - product_id (INT, FK -> products.product_id, ON DELETE CASCADE)
     - image_url (TEXT, NOT NULL)

  7. `cart_items`
     - id (INT, PK, AUTO_INCREMENT)
     - user_id (INT, FK -> users.user_id)
     - product_id (INT, FK -> products.product_id)
     - quantity (INT, NOT NULL)

  8. `orders`
     - order_id (VARCHAR 255, PK)
     - user_id (INT, FK -> users.user_id)
     - total_amount (DECIMAL 10,2, NOT NULL)
     - status (ENUM('PENDING', 'SUCCESS', 'FAILED'), DEFAULT 'PENDING')
     - created_at, updated_at (TIMESTAMP)

  9. `order_items`
     - id (INT, PK, AUTO_INCREMENT)
     - order_id (VARCHAR 255, FK -> orders.order_id)
     - product_id (INT, FK -> products.product_id)
     - quantity (INT, NOT NULL)
     - price_per_unit (DECIMAL 10,2, NOT NULL)
     - total_price (DECIMAL 10,2, NOT NULL)

4. SECURITY & AUTHENTICATION PLANNING DESIGN
--------------------------------------------------------------------------------
A. Authentication Flow:
   1. User submits registration details (/api/auth/register).
      - Server checks email & phone uniqueness.
      - Hashes password via BCrypt.
      - Assigns role (CUSTOMER by default, ADMIN seeded).
   2. User submits credentials (/api/auth/login).
      - Rate-limiter checks request count (max 5 req/min).
      - Credentials verified via BCrypt matcher.
      - System issues JWT Token signed with HMAC-SHA256 (60-min TTL).
      - Active record created in `sessions` table.
   3. Protected API requests include header: `Authorization: Bearer <JWT_TOKEN>`.
      - `JwtAuthenticationFilter` validates signature, expiration, and checks active session state in `sessions` table.

B. Multi-Step Password Recovery Flow:
   1. Endpoint `/api/auth/forgot-password`: Generates 6-digit random OTP, saves to `otps` (5-min expiry), logs to backend console and sends via SMTP.
   2. Endpoint `/api/auth/reset-password`: Verifies OTP code, updates user password, invalidates all existing user sessions.

C. Change Password Flow:
   1. Endpoint `/api/auth/change-password`: Validates current password, updates to new hashed password, terminates current session.

5. API ENDPOINTS REFERENCE
--------------------------------------------------------------------------------
Base URL Context Path: `/api`

Authentication Endpoints:
  - POST /api/auth/register       - Register a new user
  - POST /api/auth/login          - Authenticate & acquire JWT
  - POST /api/auth/logout         - Invalidate user session
  - POST /api/auth/forgot-password- Request 6-digit password reset OTP
  - POST /api/auth/reset-password - Verify OTP and update password
  - POST /api/auth/change-password- Change password (requires auth)

Product & Catalog Endpoints:
  - GET  /api/products            - Fetch all products
  - GET  /api/products/{id}       - Fetch product details
  - GET  /api/categories          - Fetch catalog categories

Cart & Order Endpoints:
  - GET  /api/cart                - Get customer cart
  - POST /api/cart/add            - Add item to cart
  - POST /api/orders/checkout     - Create order from cart items

  File Path: backend/src/main/resources/application.properties
  Verify Database Connection:
    spring.datasource.url=jdbc:mysql://127.0.0.1:3306/E-Commerce?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Kolkata
    spring.datasource.username=root
    spring.datasource.password=<YOUR_MYSQL_PASSWORD>
